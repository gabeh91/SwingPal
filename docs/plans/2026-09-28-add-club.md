# Add Club implementation plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Finish the interrupted cleanup and let golfers find, collect, review, and save catalog or custom clubs without losing selections or confusing metres and yards.

**Architecture:** Keep the existing bundled catalog and Codable bag contract. Extract catalog search and a value-type selection model from the profile view. A search-first sheet uses maker/type filters, model detail pages, a persistent selection tray, custom entry, and one review/commit step. Keep existing app-state persistence and active-round refresh.

**Tech Stack:** Swift, SwiftUI, XCTest, Xcode iOS Simulator.

## Decisions

- Search-first is the default, with optional maker/type filters. A maker-first wizard is slower for golfers who already know their model; a catalog expansion cannot repair the interaction problems and requires separate source verification.
- Search matches maker, model, category, club number and loft, ignoring case and punctuation. All query terms must match a model. Filters compose with search and offer a clear reset.
- Selections survive search/filter/navigation changes and mixing catalog/custom clubs. Nothing reaches the bag until the final Add action. Dismissal warns whenever there is unfinished work.
- Review labels catalog carry values as editable starting estimates. Display and parse the user's chosen unit; retain integer metres in storage. Reject empty, nonpositive, nonnumeric and excessive carries. Putters do not ask for a full-swing carry.
- Suppress identical clubs within a batch or already in the bag, while preserving existing records and allowing distinct models. Display a soft 14-club reminder rather than restricting a user's collection.
- The bundled catalog is a starting list, not a claim that every model or head is available. Offer custom entry from empty search and model detail; do not invent product specifications.
- Work in the existing dirty workspace as requested. Baseline copy is `/tmp/swingpal-codex-baseline-20260928`; do not commit unrelated inherited changes.

### Manufacturer catalog follow-up

The earlier limitation about unverified bundled club options is superseded by the [manufacturer catalog snapshot and maintenance notes](../data/club-catalog.md). This follow-up replaces generic families/ranges with sourced models while preserving saved bags.

### Alphabetical browsing follow-up

The expanded 650-model picker groups results by the model's initial letter, with numbered names under `#`. Models use natural alphabetical/numeric ordering within each section, with maker and ID as deterministic tie breakers. Search and maker/type filters are applied before grouping, so empty sections disappear. iOS 26 uses the native side index; earlier supported iOS versions offer a Jump to letter menu.

Validation: 21 focused Add Club, manufacturer catalog and remote catalog tests passed (`/tmp/swingpal-alphabetical-tests.log`). On the isolated iOS 26 simulator, the full catalog displayed letter sections and a side index; tapping S jumped directly to its models. Searching XXIO reduced the list to eight numbered models, and a model opened correctly from that section. The earlier-iOS fallback compiled against the iOS 18 deployment target but was not interactively checked on iOS 18.

### Index magnification follow-up

The side index now uses a custom control across supported iOS versions. Touch dragging or pointer hover magnifies the active letter up to 2.3×, with a smaller effect on nearby letters. Letters move inward and apart while their hit areas remain fixed. Hover only changes appearance; touching or dragging jumps between sections. The index returns to normal on release or pointer exit, and resets when search changes the available letters. Reduce Motion uses colour and weight without zooming; VoiceOver exposes an adjustable index. A Jump to letter menu is also available on all supported versions.

Validation: 21 focused tests passed (`/tmp/swingpal-letter-magnification-tests.log`), and the final animation refinement built successfully (`/tmp/swingpal-letter-magnification-build.log`). Independent static review found no actionable issues. The custom index was visible in Simulator and its menu navigated to S. Automated coordinate gestures became unavailable during this check, so the live drag/hover animation was not visually confirmed.

### Catalog selection and unfinished custom drafts

Fixed a routing bug where opening the custom form from a catalog model filled maker/model suggestions, counted them as unfinished work, and replaced the catalog review action with “Finish custom club.” Suggested fields now establish a clean baseline. Actual edits remain intact across navigation, while the catalog's main action stays Review/Add selected clubs. Genuine unfinished custom drafts have separate Edit/Discard actions; saving selected clubs asks before discarding such a draft. Untouched suggestions require no confirmation or custom club.

The regression run demonstrated six assertion failures in the old suggestion/routing behavior (`/tmp/swingpal-custom-routing-red.log`). ### Brand, model and version hierarchy

Browsing now starts with the 22 brands rather than every catalog family. Within a brand, related versions are grouped under model ranges, for example PING → G440 → MAX/LST/SFT → club number or loft. The version screen separates drivers, fairway woods, hybrids and irons. A range with one matching version opens its club options directly. Search and type filters narrow the hierarchy, with the query visible on both brand and model screens. Brand/model lists retain the magnifying alphabetical index.

Grouping is display-only and derived from the existing catalog names with conservative brand-specific range prefixes; unrecognized names remain distinct. Exact family IDs, names, categories and selectable options remain unchanged, so saved bags and duplicate detection keep working. Future model lines outside the recognized patterns remain available under their full model names.
